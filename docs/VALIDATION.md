## Agent 入口缺失的根因

用户普通 Chrome 截图显示备用账号已有 Agent。自动化会话实测视口仅为 762×533（headless 默认屏幕 800 宽），Agent 控件查询为空；相同账号、项目仅将视口设为 1920×1080 并刷新，立即出现“智能体指令”控件。不是账号权限缺失或中文按钮识别问题，而是窄屏响应式布局隐藏桌面 Agent 控件。

已在新建及重新附加的浏览器页面统一设置桌面视口，同时指定 Chrome 启动窗口大小。正常关闭并重新启动备用账号的独立浏览器后，再次验证 1920×1080、Agent 控件存在且仍登录；不需重新桥接。Node 20/24 均通过 57 项回归测试。

随后另提交同一极短片段到备用账号 Agent，实际走 AUTO_APPROVE 而不是普通界面的 direct_submit。新任务正常返回 processing，使用同一编号查询后自动完成原始尺寸下载，无人工改任务状态、点击生成或救下载。MP4/H.264、4 秒、1280×720、673,015 字节；完整 FFmpeg 解码通过，复核帧为纸艺机器人举手。SHA-256：`0221e70876343e60ecc30e0254eb7269af77827ee271ceca15840528d349baa48`。备用余额由 50 降至 43，本次耗 7 点，无购买或放大。

当前已分别验证“原账号额度拒绝后自动路由至备用”和“备用桌面 Agent 正常生成、下载”；修复视口后尚未重跑同一个新任务从原账号拒绝一直到备用下载的组合验收，避免重复消耗额度。普通界面先前失败的后端原因仍未确定；视口原因解释的是 Agent 入口缺失，不将两者混为同一已证实根因。

后续双账号实测：备用账号曾进入工作区，但关闭登录窗口后再次读取转到未登录页面，未提交生成任务。发现 CDP `browser.close()` 后立即终止 Chrome 的关闭路径，改为先请求 `Browser.close` 并等待进程退出，超时才强制关闭；会话保留效果尚待再次登录后实测。另修正额度警告判断为提交前执行，并增加“提交后出现警告不能换号重提”的回归测试。
